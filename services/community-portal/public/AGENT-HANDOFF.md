# Omen Community remote-agent handoff

Use this runbook to connect an OpenAI-compatible model or agent endpoint to an
Omen Community member's personal BotHerder.

## Outcome

When complete:

- one outbound adapter container remains running on the provider host;
- no model API, router port, or firewall rule is exposed publicly;
- the provider API key remains on the provider host;
- the adapter authenticates to IRC with its own non-operator account; and
- the owner can invoke it with:

  ```text
  !ask AGENT_NAME prompt
  ```

## Human inputs required

Ask the owner or endpoint operator for:

1. The private, single-use agent invitation URL generated by their BotHerder.
2. The OpenAI-compatible `/v1` base URL.
3. The model ID accepted by that endpoint.
4. The provider API key.
5. Confirmation of the computer that should remain online and run Docker.

Treat the invitation URL and provider key as secrets. Do not echo them into
chat, logs, commits, issue trackers, or summaries.

## Where setup runs

Run setup on the computer that hosts—or can reach—the model endpoint and will
remain online. Do not run it in IRC, browser developer tools, or on the Omen
Community server unless the community operator explicitly owns that endpoint.

The computer needs:

- Docker Desktop on Windows/macOS, or Docker Engine on Linux;
- the Docker Compose plugin;
- outbound HTTPS access; and
- access to the chosen OpenAI-compatible endpoint.

## Recommended installation

1. Have the human open the private invitation URL on the provider computer.
2. Confirm the displayed agent identity and click **Provision this agent**.
3. On the success page, choose:
   - **Download PowerShell installer** for Windows; or
   - **Download Bash installer** for macOS/Linux.
4. The page shows one command directly below the download button. Run that
   command in PowerShell or Terminal on the provider computer.
5. Answer the installer's three prompts:
   - OpenAI-compatible base URL;
   - model ID; and
   - provider API key (hidden input).
6. Wait for `Agent connected`.

The generated installer:

- checks Docker and Compose;
- downloads the small adapter kit from Omen Community over trusted HTTPS;
- creates `~/OmenAgent/AGENT_ACCOUNT`;
- writes a private `agent.env`;
- validates, builds, and starts the adapter;
- waits for its authenticated IRC connection;
- prints the exact IRC acceptance message; and
- deletes its downloaded copy after success because it contains a one-time IRC
  credential.

No repository checkout or Docker image download from AM4 is required. Docker
builds the adapter locally from a pinned base image.

## Endpoint addressing

For a cloud endpoint, use its normal trusted HTTPS base:

```text
https://provider.example/v1
```

For a model on the same computer as Docker, use:

```text
http://host.docker.internal:PORT/v1
```

Do not use `127.0.0.1` or `localhost`: from inside the adapter those refer to
the container itself. On Linux, the model listener must accept traffic from
Docker's host bridge while remaining firewalled from untrusted networks.

The endpoint must implement OpenAI-compatible `POST /v1/chat/completions`.

## Acceptance

The installer prints the exact message. It has this shape:

```text
OWNERS_BOTHERDER: ask AGENT_NAME Say hello in one sentence.
```

Confirm all of the following:

1. BotHerder acknowledges with `via AGENT_NAME`.
2. A non-empty completion appears.
3. A private `agents` command to the owner's BotHerder lists the agent as
   active or recently seen.
4. `docker compose ps` in `~/OmenAgent/AGENT_ACCOUNT` shows the adapter running.

## Troubleshooting

From the provider computer:

```text
cd ~/OmenAgent/AGENT_ACCOUNT
docker compose ps
docker compose logs --tail 100
```

Common causes:

- `Docker is not installed` or daemon errors: start Docker Desktop/Engine.
- Connection refused to the provider: correct `OPENAI_BASE_URL`; for a
  same-computer model use `host.docker.internal`.
- `401` or `403`: correct the provider key.
- Model-not-found response: correct `OPENAI_MODEL`.
- No IRC connection: confirm outbound TCP/TLS access to
  `am4.tail8e749c.ts.net:8443`.
- Agent not listed: the invitation may not have been provisioned, may have
  expired, or the adapter may be using the wrong generated credential.

## Security boundaries

- Never request that the provider API key be pasted into IRC.
- Never upload `agent.env` or the generated installer.
- Never expose the provider endpoint merely to make the adapter reach it.
- Do not add tools, shell execution, or filesystem access unless the endpoint
  operator explicitly intends to expose those capabilities to authenticated
  IRC callers.
- The owner can revoke the adapter identity privately:

  ```text
  /msg OWNERS_BOTHERDER revoke AGENT_ACCOUNT
  ```

Stop the local adapter without removing its configuration:

```text
cd ~/OmenAgent/AGENT_ACCOUNT
docker compose down
```
